# DevProxy 2.3.5 — прокси для выбранных приложений Windows

DevProxy запускает отмеченные IDE и инструменты с настройками выбранного прокси. В этой версии интерфейс полностью на русском: добавление, изменение, удаление и проверка прокси; автоматическое обнаружение установленных приложений; понятные сообщения об ошибках.

**Это этап 1: приложение передаёт настройки прокси, но не перехватывает весь сетевой трафик через WFP.** Приложения или дочерние процессы, игнорирующие настройки, могут подключаться напрямую. Локальный туннель сам никогда не обходит выбранный прокси. Запуск с требованием гарантированной блокировки прямого доступа отклоняется.

## Исправление 2.3.5

Исправлена потеря идентификатора старого профиля при включении постоянного режима. Из-за неё действующий мост возвращал HTTP 502 / profile_unavailable при сохранённых параметрах и доступном пароле; браузер показывал ERR_TUNNEL_CONNECTION_FAILED. Теперь миграция идентификатора сохраняется. При неудачном включении новая сессия закрывается, а настройки откатываются.

Перед открытием браузера входа проверяются профиль, фактический туннель к accounts.google.com, сертификат Google и локальный приёмник возврата OAuth. Недоступный мост и устаревшая ссылка показываются в DevProxy. Вход с localhost callback возвращается в Antigravity автоматически; код нужно вставлять только если его запрашивает сам клиент. Данные аккаунта и каталог пользовательского профиля не очищаются.

Проверено локально: 185 тестов и запуск готовых Windows CLI/GUI. Повторный вход в аккаунт завершает сам пользователь; транспортная проверка не заменяет авторизацию Google.

## Постоянный режим и трей

Выберите прокси, отметьте приложение и нажмите **«Включить постоянно»**. DevProxy сохраняет правило, перенастраивает существующие пользовательские ярлыки в меню Пуск, на рабочем столе и в закреплениях панели задач. Если подходящих ярлыков нет, создаётся ярлык в **Пуск → DevProxy**. После этого запускайте приложение его ярлыком: агент поднимется сам, если ещё не работает. Окружение прокси получает только запускаемое приложение и его потомки. Пароль остаётся в хранилище Windows.

Агент запускается при входе пользователя в Windows. **Крестик и сворачивание прячут окно в трей**, сохраняя соединения. Щёлкните значок для открытия настроек. Меню значка позволяет запускать настроенные приложения, отключать постоянный режим и полностью выходить. **«Выход — остановить приложения»** закрывает агент и управляемые им приложения; сохранённые правила остаются для следующего запуска.

Для отмены отметьте приложение и нажмите **«Вернуть обычный запуск»**, затем перезапустите его. Исходные ярлыки восстанавливаются; чужие изменения не затираются. После отключения последнего правила восстанавливается предыдущая запись автозапуска. Это фоновый агент пользователя: установка системной службы и права администратора не нужны.

Постоянный режим действует через настроенные ярлыки. Прямой запуск исходного EXE, другие системные пользователи, ярлыки общего меню Пуск и файловые ассоциации автоматически не перехватываются. При первом включении полностью закройте IDE, чтобы она не передала запрос старому процессу без настроек прокси. Не перемещайте папку с EXE DevProxy после настройки; сначала отмените правила либо перенастройте их из новой установки.

**Antigravity:** исправлен чёрный экран из-за перенаправления её внутреннего `https://127.0.0.1` во внешний прокси. Локальные `localhost`, `127.0.0.1`, `::1` исключены из проксирования; проверка TLS не отключается. Antigravity и постоянные запуски Electron используют существующий профиль, сохраняя авторизацию и настройки.

## Что нового в 2.3.4

- **Исправлено повреждение потока через HTTPS-прокси.** Прямой вызов `shutdown(SHUT_WR)` на SSL-сокете очищал SSL-слой Python: последующие чтения могли возвращать шифротекст. Теперь TLS-слой сохраняется до общего закрытия, а большие ответы передаются байт-в-байт.
- **Новое соединение использует актуальные адрес, порт и пароль.** Рабочий мост больше не хранит снимок профиля: каждое новое соединение читает сохранённые метаданные и секрет согласованно, а уже открытые потоки продолжают работать.
- **Повтор TLS-рукопожатия ограничен.** До трёх попыток только при обрыве в самом начале рукопожатия с прокси, в пределах общего времени. Ошибка сертификата, неверный протокол, `403`/`407` и отказ белого списка не повторяются и не обходятся.
- **Понятные ошибки.** Отличаются недоверенный сертификат, обрыв TLS и прочие ошибки TLS; сообщение содержит адрес назначения, этап, код и HTTP-статус. Ошибка одного адреса не стирается успехом другого.
- **Интерфейс не зависает.** Состояние фонового режима читается из неблокирующего кеша, поэтому окно и IPC не ждут блокировку при изменении правил. Сбои постоянного туннеля показываются в статусе.
- **Переименование профиля.** Правила постоянного режима, зарезервированный порт и выбранный профиль переносятся на новое имя; висящих ссылок на удалённое имя не остаётся.

Добавлены постоянная идентичность профиля, актуальные данные в CLI, обработка обоих направлений TLS-ожиданий, резервные маршруты и браузер входа. Проверки выполняются полным набором автоматических тестов и smoke tests готовых CLI/GUI EXE. Точный результат и живые проверки Antigravity приведены в отчёте проверки.

Локальная проверка 2.3.4: **175 тестов**, сборка и запуск упакованных CLI/GUI. Пользователь подтвердил фактический ответ Antigravity. Отдельные начальные TLS-обрывы с прокси наблюдались; работа входа при отключённом VPN отдельно не подтверждена. См. [отчёт проверки](docs/RELEASE_VERIFICATION.md).

Одновременно к одному HTTPS-прокси открываются максимум два TLS-рукопожатия; установленные потоки работают параллельно.

## Как начать

**Вход Antigravity без VPN:** нажмите вход в самом приложении, затем **«Вход Antigravity через прокси…»** в DevProxy. Свежая ссылка Google из журнала подставляется автоматически; также её можно вставить вручную. Откроется отдельный профиль Chrome/Edge/Brave/Яндекс Браузера через тот же мост. При локальном callback вход возвращается в Antigravity автоматически. Если клиент отдельно запросит код, вставьте его туда. Основной браузер и его системные настройки не меняются. Выход закрепляется до завершения этой сессии DevProxy; при его недоступности вход показывает ошибку вместо смены страны.

**Несколько серверов:** добавьте их как обычные прокси и нажмите **«Резервные прокси…»** у основного профиля. Можно выбрать до четырёх резервов, то есть группу из пяти серверов. Автоматическое переключение возможно при транспортном сбое до CONNECT; выбранный выход остаётся основным для текущей сессии. Запрет назначения, неверный пароль и недоверенный сертификат не запускают переключение. Запросы и генерации после отправки не повторяются. Российский сервер включайте лишь как явно настроенный маршрут: двухэтапный транзит программа автоматически не создаёт.

Изменение адреса, пароля и названия сохранённого профиля применяется к новым соединениям работающего моста. Локальный порт и открытые потоки сохраняются. Удаление и создание одноимённого профиля не переназначает старую сессию.

Во всех текстовых полях работают **Ctrl+V** (в том числе в русской раскладке), **Shift+Insert** и меню правой кнопки мыши **«Вставить»**. **Ctrl+A** выделяет весь текст; **Ctrl+C/Ctrl+X** копируют/вырезают выделение. Вставка доступна также в поле пароля и окне ссылки прокси.

1. Распакуйте Windows-архив и запустите **devproxy-gui.exe**.
2. При первом запуске установленные IDE и инструменты появятся в списке автоматически. Результаты и галочки сохраняются; повторный поиск доступен кнопкой **«Найти приложения»**.
3. В блоке **«Прокси»** нажмите **«Добавить»**.
4. Введите название, тип, адрес сервера и порт. Если прокси требует авторизацию, включите галочку и введите логин/пароль. Готовую ссылку можно вставить через **«Вставить ссылку прокси»** — поля заполнятся автоматически.
5. При желании проверьте разрешённый вашим прокси сайт кнопкой **«Проверить»**, затем нажмите **«Сохранить»**. Проверка не обязательна для запуска.
6. Отметьте нужные приложения в столбце **«Выбор»** и нажмите **«Запустить выбранные»**.

**«Изменить»** позволяет изменить адрес, порт, тип, название и авторизацию профиля. При редактировании сохранённый пароль не показывается. Оставьте поле пустым, чтобы использовать прежний пароль, или введите новый для замены.

**«Остановить»** завершает приложения данной сессии и их дочерние процессы, затем закрывает туннель. Остальные запущенные приложения и системные настройки прокси не изменяются.

Если приложение отсутствует, нажмите **«Добавить EXE…»** и выберите его настоящий исполняемый файл. Можно убрать ненужную запись из списка. Повторный автопоиск может вернуть установленное приложение в список.

## Автопоиск IDE и инструментов

Каталог включает VS Code, VS Code Insiders, VSCodium, Cursor, Windsurf, Antigravity, Visual Studio, IntelliJ IDEA, PyCharm, WebStorm, Rider, GoLand, CLion, PhpStorm, RubyMine, DataGrip, RustRover, Fleet, Android Studio, Zed, Sublime Text, Notepad++, **Codex CLI, Codex Desktop, OpenCode, Claude Code и Git**.

Поиск проверяет стандартные каталоги Windows, PATH, реестр установленных программ и App Paths, ярлыки меню «Пуск», известные MSIX-пакеты, версии JetBrains Toolbox, каталоги CLI и npm-пакетов. Весь диск не сканируется. Отсутствующие приложения не устанавливаются. Найденные приложения добавляются **без автоматического запуска**; пользователь выбирает галочки.

Для CLI, установленного через npm, DevProxy предпочитает настоящий EXE. Если пакет объявляет JavaScript-точку входа, используется node.exe с файлом скрипта, без запуска .cmd или интерпретации оболочкой. Защищённые пакетные EXE могут не разрешать такой запуск; тогда используйте обычную установку приложения. Codex Desktop не путается с одноимённым CLI-worker.

## Прокси и безопасность

Поддерживаются HTTP forward / HTTP CONNECT, HTTPS-прокси с проверкой сертификата, SOCKS5 с логином/паролем, адреса IPv4/IPv6. Для SOCKS5 имена назначения разрешаются на стороне прокси.

Пароли сохраняются в **Диспетчере учётных данных Windows**, а JSON-профили содержат только ссылку на секрет. Пароли не передаются в аргументах процессов, переменных окружения, логах или настройках IDE. Если защищённое хранилище недоступно, сохранение профиля завершается ошибкой. Переименование и редактирование сохраняют пароль; при ошибке записи метаданных откатывается изменение секрета.

Basic/SOCKS-аутентификация на незащищённом upstream-соединении видна в этой сети. Используйте доверенную сеть или HTTPS-прокси. TLS не перехватывается и проверка сертификатов не отключается.

Локальный listener привязан к 127.0.0.1 (или явно ::1); количество соединений и буферы ограничены. Другие локальные процессы могут использовать listener, пока сессия активна: loopback не является границей авторизации процессов.

## Что означает ошибка проверки

Вместо общего «ProxyError» интерфейс показывает причину:

- **Логин или пароль отклонён** — измените данные авторизации.
- **Сервер отказал в подключении** — проверьте адрес, порт и запущен ли прокси.
- **Имя сервера не найдено** — проверьте адрес и DNS.
- **Прокси не ответил вовремя** — проверьте сеть и доступность сервера.
- **HTTP 403/другой статус для сайта** — прокси может запрещать доступ к выбранному сайту.
- **Ошибка сертификата** — исправьте сертификат или доверие; проверка TLS не отключается.

Сайт для проверки по умолчанию — github.com:443. Его можно изменить в основном окне или форме профиля. Успешная проверка означает, что прокси принял соединение к этому сайту; она не доказывает работоспособность всех сервисов IDE или отсутствие обхода прокси.

## Прокси со списком разрешённых сайтов

Запуск приложения и фонового агента не требует доступа к github.com или другим диагностическим сайтам. DevProxy не добавляет свой список разрешённых внешних адресов: назначения запрашивает само приложение, а решение о доступе принимает ваш прокси. Кнопка «Проверить» проверяет только указанный вами сайт.

Если сайт запрещён сервером прокси, DevProxy не обходит запрет и не переключает свой туннель на прямое соединение. Для работы IDE её API, вход в аккаунт, расширения и загрузки должны быть разрешены у поставщика прокси. Успешная проверка одного сайта не подтверждает доступность остальных. В релиз не включены чужие профили, пароли или списки доступа.

## Ограничения текущего этапа

Нет WFP-драйвера, полной защиты от прямого выхода всех дочерних процессов, независимых DNS/UDP/IPv6-запросов, перехвата уже запущенных приложений или автоматических обновлений. Некоторые среды игнорируют HTTP_PROXY/HTTPS_PROXY. Обнаружение приложения не означает подтверждённую поддержку каждого его сетевого компонента.

Electron-редакторы запускаются с временным отдельным профилем, чтобы не передать запуск уже работающему экземпляру. Настройки и вход в аккаунт этой сессии будут новыми; исходный пользовательский профиль не перезаписывается. Windows Job Object завершает дерево сессии при остановке и аварии DevProxy. Жёсткая авария может оставить временный каталог, но не системные proxy/WFP-правила.

## CLI и сборка

Для запуска из исходников нужен Python 3.11+ с Tk:

    python devproxy.py gui

CLI остаётся доступен:

    python devproxy.py profile add socks5://proxy.example:1080 --name office --username alice
    python devproxy.py doctor --profile office
    python devproxy.py run vscode --profile office
    python devproxy.py run "C:\Apps\Editor\Editor.exe" --profile office

Пароль вводится скрытым запросом, без аргументов командной строки.

Сборка Windows:

    python -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
    .\.venv\Scripts\python.exe tools/build_windows.py

Скрипт запускает тесты, собирает CLI/GUI EXE и проверяет готовые исполняемые файлы. Python 3.14 с Tcl/Tk 9 поддерживается явной упаковкой ресурсов. Результаты — dist/devproxy.exe, dist/devproxy-gui.exe и dist/devproxy-windows-x64.zip. Проверка Credential Manager требует нормальной пользовательской Windows-сессии.

[Технический отчёт](REPORT.md) содержит первоначальный аудит, ограничения архитектуры и результаты проверок. Linux/macOS не являются целевыми платформами выпуска.
