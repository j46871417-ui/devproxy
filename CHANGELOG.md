# DevProxy 2.3.4

- Исправлены ожидания SSLWantRead/SSLWantWrite в обоих направлениях передачи. Повторы записи используют одинаковые данные; сетевые ошибки попадают в диагностику назначения.
- Профиль имеет постоянный идентификатор: переименование сохраняет действующий мост, порт и открытые потоки. CLI также использует актуальные данные сохранённого профиля.
- Добавлены резервные маршруты из существующих профилей. Переключение допускается до CONNECT при транспортном сбое, с ограничением времени и паузой для недоступных выходов. Пароль, сертификат и белый список не обходятся.
- Добавлен отдельный браузер входа Antigravity через тот же мост. Выход закрепляется для входа; свежая ссылка Google может читаться из локального журнала без сохранения или вывода в технические логи.
- Фоновый статус читается одним снимком; периодическое обновление не создаёт неограниченные потоки. Версия доступна через CLI и IPC.

- Одновременно к одному HTTPS-прокси открываются максимум два TLS-рукопожатия; очередь учитывает общий deadline, открытые потоки не сериализуются.

Проверено локально: 175 тестов и запуск готовых Windows CLI/GUI. Пользователь подтвердил фактический ответ Antigravity. Отдельные начальные TLS-обрывы наблюдались; вход при отключённом VPN отдельно не подтверждён.

# DevProxy 2.3.3 (предварительный кандидат)

Исправление надёжности соединения через HTTPS-прокси и корректная работа с профилем.

- **Исправлено повреждение потока через HTTPS-прокси.** Прямой вызов `shutdown(SHUT_WR)` очищал SSL-слой Python, и дальнейшие чтения могли возвращать шифротекст. Замер воспроизводился и на версии 2.3.2: поток 256 КиБ через HTTPS-прокси повреждался на байтах, начиная с первого полузакрытия. Теперь SSL-слой сохраняется до общего закрытия, поток передаётся байт-в-байт.
- **Новое соединение использует актуальные адрес, порт и пароль.** Мост больше не хранит снимок профиля: метаданные и секрет читаются согласованно для каждого нового соединения, уже открытые потоки не разрываются. При недоступном пароле новое соединение отклоняется и не подключается напрямую.
- **Ограниченный повтор TLS-рукопожатия.** До трёх попыток только при обрыве в самом начале рукопожатия с прокси, в пределах общего времени. Ошибка проверки сертификата, неверный протокол, `403`/`407` и отказ белого списка не повторяются; повтор возможен только до CONNECT и без прикладных данных.
- **Понятные и безопасные ошибки.** Различаются недоверенный сертификат, обрыв TLS и прочие ошибки TLS. Сообщение содержит адрес назначения, этап, тип, код и HTTP-статус. Ошибка одного адреса остаётся видимой после успеха другого; история ограничена. Пароль, логин, заголовок `Proxy-Authorization` и полные URL с параметрами не выводятся.
- **Интерфейс не зависает.** Состояние постоянного режима читается из неблокирующего кеша, поэтому окно и IPC не ждут блокировку при изменении правил. Сбои фонового туннеля показываются в статусе, не затирая результат действия пользователя.
- **Переименование профиля.** Правила постоянного режима, зарезервированный порт и выбранный профиль переносятся на новое имя; ссылок на удалённое имя не остаётся.

Проверено: 159 автоматических тестов (116 исходных + 43 новых), сборка Windows CLI/GUI, запуск готовых EXE и побайтовая целостность потока 256 КиБ через HTTPS-прокси. Интерактивную работу Antigravity через профиль «Прокси 1» нужно подтвердить отдельно.

DevProxy передаёт настройки прокси приложениям. Полный перехват трафика через WFP и гарантированная блокировка прямых подключений не реализованы. Доступ к сайтам определяет ваш прокси; запреты его белого списка не обходятся. Исполняемые файлы пока не подписаны сертификатом издателя.
