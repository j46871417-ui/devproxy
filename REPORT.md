# DevProxy 2.3.1 — проверка фонового режима

Реализовано без делегирования другим агентам. Windows, Python 3.14, Tkinter, native Win32 tray и PyInstaller.

## Причина чёрного экрана Antigravity

Локально прочитаны метаданные установленной Electron-сборки и её исходники внутри app.asar. Её WINDOW_ORIGIN — `https://127.0.0.1`, интерфейс загружается с локального сервера. Прежний аргумент `--proxy-bypass-list=<-loopback>` и пустой NO_PROXY отправляли эти обращения во внешний прокси. Исправлены локальные исключения; TLS verification сохранён. Antigravity запускается с обычным профилем вместо пустого временного.

## Фоновый режим

Добавлены native tray с восстановлением после перезапуска Explorer, закрытие/сворачивание в трей, явный выход, single-instance mutex, защищённый named pipe с отдельным случайным ключом. IPC принимает только ID сохранённых правил и проверенные аргументы; произвольный EXE через IPC не передаётся.

Постоянные правила сохраняют приложение, профиль и фиксированный loopback-порт. Пользовательские ярлыки запускают broker DevProxy; он восстанавливает агент при необходимости и запускает приложение с его собственным окружением прокси. Изменения журналируются до внешней записи; отмена сохраняет чужие изменения. Автозапуск хранится только в HKCU, его предыдущая запись восстанавливается после отключения последнего правила.

## Проверки

- Полный набор после реализации: 116 тестов, OK; сборка выполняет весь набор перед упаковкой.
- Локальный HTTP-интерфейс в выбранном процессе отвечает напрямую, не вызывая upstream proxy; внешние запросы и outage по-прежнему проверяются отдельно.
- Проверены постоянный порт, занятый порт без тихой замены, сохранение аргументов ярлыка, восстановление исходного состояния, конфликтные изменения, rollback при ошибке автозапуска, выбор зарегистрированного приложения.
- Native Windows: проверены Shell_NotifyIcon и доставка клика в очередь, настоящий authenticated named pipe, mutex, настоящий COM-ярлык (создание → broker → восстановление → удаление тестового ярлыка), русские пути/аргументы в PowerShell 5.
- Предыдущие исправления ввода и точки входа GUI включены в полный набор. Синтетические Ctrl+V тесты теперь используют реальный физический код клавиши Windows, поэтому проверка работает при активной русской раскладке.

## Практические ограничения

Это proxy-aware режим, а не WFP-перехват всего трафика. Программы могут игнорировать proxy settings. Постоянные правила работают через пользовательские ярлыки; прямой EXE и файловые ассоциации не перехватываются. Нужно закрыть существующий процесс IDE перед первым запуском с новым правилом. Не заявляется полная изоляция внешнего DNS/UDP/IPv6.

## Совместимость с белым списком назначений

Убран обязательный CONNECT к диагностическому github.com перед ручным запуском. Интеграционный тест использует локальный прокси, который отвечает 403 на этот сайт, но разрешает адрес приложения: GUI запускает настоящий дочерний процесс, его запрос проходит через туннель, посторонних назначений нет. Постоянный режим также не требует диагностических подключений. Политика доступа внешнего прокси сохраняется; тест не подтверждает состав или доступность реального списка пользователя.
